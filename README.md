# ウッドプラスチックテクノロジーポータル（GitHubのIssueから更新する仕組み）

GitHubのIssueに `@claude` と書いて頼むだけで、ニュースの作成、採用情報の更新、文章の修正、画像の差し替えなどができるホームページです。更新作業はすべてGitHubの中で完結します。

AIは3つから選べます。`@claude`（Claude）、`@chatgpt`（ChatGPT）、`@gemini`（Gemini）のどれで呼んでも、同じ流れ・同じルール・同じ道具で作業します（下の図の `@claude` は、使うAIの名前に読み替えてください）。

```
① Issueに「@claude ○○したい」と書いて作成
      ↓ 自動
② Claudeがコメントで返事（質問・文章の提案・修正内容の報告）
      ↓ 「@claude これでOK」とコメント（小さな修正は①のあとすぐ保存されます）
③ Claudeが下書きを保存
      ↓ 自動
④ 確認用ページ（GitHub Pages）が更新され、URLがコメントで届く
      ↓ 見た目を確認して、Claudeの返事の「Create PR」から公開申請を作る
⑤ 公開申請で「Squash and merge」→「Confirm squash and merge」
      ↓ 自動
⑥ 本番サイトに反映
```

- **予約公開**：ニュースの日付を未来にすると、その日の朝6時ごろに自動で公開されます
- **取り下げは削除**：ニュース・求人・職種・社員紹介を取り下げるときは、AIが中身・ページ・その項目だけで使っていた画像を消します（`tools/remove.py`）。消したものは変更の記録に残り、「前に出していた求人をもう一度出したい」と頼めば、記録から探して元どおりに戻せます（`tools/history.py`）
- **写真を外す**：「お問い合わせの写真を外して」のように頼むと、AIが写真をページから外します（`tools/remove.py photo`。どこでも使わなくなった画像のファイルも消します）。外せるのは、外してもページの形が崩れない場所（見出しの下の大きな写真、ニュースの本文の写真、社員紹介のインタビューの途中の写真）だけです。写真の並び・カード・背景や、職種・社員紹介の人物写真・製品の写真は、外すと形が崩れたり「写真予定」の枠が出たりするので、AIは理由を伝えて差し替えを提案します（手でページの写真を消すと `--check` がエラーにします）。外した写真は、変更の記録から戻せます
- **下書き・非公開**：ニュースや求人を「下書き」にすると確認用ページにだけ表示されます。「サイトに残したまま隠したい」とはっきり頼んだときだけ「非公開」にします（どちらにも表示されません）
- **差し戻し**：すべての変更が履歴として残るので、いつでも前の状態に戻せます
- **リンク・題名などの軽微な修正**：「フッターの関連サイトに〇〇 https://… を足して」「参画企業のロゴから各社のサイトに移れるように」「このリンク先を変えて」「この言葉にリンクを付けて」「ページの説明文を変えて」のように頼めます。関連サイトは `site.json` の `related` にまとめてあり、全ページのフッターに自動で入ります。メニューや欄を足す・消す・並べ替えるなど、レイアウトが変わるものは管理者に相談してください
- **画像の自動調整**：スマートフォンの大きな写真も、自動で縮小・向きの補正・撮影場所などの情報の削除をしてから使います
- **写真の加工**：「奥の人の顔をぼかして」「ホワイトボードが読めないように」「人物を中心に縦長に切り抜いて」「トーンを合わせて」「goto_09 は使わないで」のように頼めます。AIは、主役以外の人の顔や読める文字が写っていないかを、指示がなくても確かめ、切り抜きで外すか、別の写真にするかを聞き返します。**ぼかしは、頼まれるまで行いません。** 頼まれたときも、AI のぼかしは精度が高くない（ぼかしたところが目立つ、主役の顔にかかることがある）ことを伝え、切り抜きや別の写真、画像編集のソフト・制作会社での加工を先に提案します。それでもと頼まれたときだけ、境目をなじませてぼかします（ぼかしの見落としがないかは、確認用ページで人の目でも確かめてください）

## 1. 最初の設定（1回だけ）

### 1-1. Claude GitHub App をリポジトリに入れる

1. https://github.com/apps/claude を開き、「Configure」を押します
2. 自分のアカウントを選び、「Only select repositories」でこのリポジトリを追加して保存します

### 1-2. シークレットを登録する

**Settings → Secrets and variables → Actions** に、次を登録します。本番のアドレスやサーバーの場所はファイルに書かず、ここに登録します（別の環境に移しても、ファイルを直さずに済むように）。

| 名前 | 中身 |
| --- | --- |
| `CLAUDE_CODE_OAUTH_TOKEN` | パソコンのターミナルで `claude setup-token` を実行して表示されたトークン |
| `FTP_SERVER` | XserverのFTPホスト名（`sv○○○○.xserver.jp` の形） |
| `FTP_USERNAME` | FTPのユーザー名 |
| `FTP_PASSWORD` | FTPのパスワード |
| `FTP_SERVER_DIR` | サーバーの中のアップロード先。`/` で終わる形（例：`./example.com/public_html/`）。登録がないと公開が止まります |
| `SITE_URL` | 本番サイトのアドレス（例：`https://example.com/`）。SNSで共有されたときの画像に使います。なくても公開できます |

### 1-3. 確認用ページ（GitHub Pages）を使えるようにする

1. **Settings → Pages** の「Build and deployment」の **Source** を **「GitHub Actions」** に変えます
2. **Settings → Environments** の **「github-pages」** を開き、「Deployment branches and tags」を **「No restriction」** に変えて保存します（なければ、一度下書きを保存すると作られます）

- 非公開（Private）のリポジトリでGitHub Pagesを使うには、GitHubの有料プランが必要です
- 確認用ページのURLは、知っていれば誰でも見られます（検索エンジンには載らない設定にしています）

### 1-4. 公開ボタンを「Squash and merge」だけにする

**Settings → General → Pull Requests** で、「Allow squash merging」だけにチェックを残し、その下の「Default commit message」を「Pull request title」にします。

### 1-5. ChatGPT と Gemini を使えるようにする（使う場合だけ）

`@chatgpt`・`@gemini` で呼ぶには、それぞれの API キー（使った分だけ払う契約）を取って、シークレットに登録します。担当者の方のアカウントは要りません。

| 名前 | 取り方 |
| --- | --- |
| `OPENAI_API_KEY` | https://platform.openai.com/ にログインし、支払い方法を登録してから「API keys」→「Create new secret key」で作ったキー |
| `GEMINI_API_KEY` | https://aistudio.google.com/ にログインし、「Get API key」→「APIキーを作成」で作ったキー。**支払い（請求先アカウント）を設定した有料の状態で使ってください**（無料の枠では、送った内容がGoogleのサービス改善に使われる扱いのため） |

- 登録先は 1-2 と同じ **Settings → Secrets and variables → Actions** の「Secrets」です
- 使うモデルを変えたいときは、同じ画面の「Variables」に `OPENAI_MODEL`・`GEMINI_MODEL`（モデルの名前）を登録します。登録しなければ、それぞれの標準のモデルを使います
- 利用規約や料金は変わることがあるので、契約の前に各社の最新の案内を確かめてください

### AIは何を読み込んで動くのか

Claude は `CLAUDE.md` を、ChatGPT と Gemini は `AGENTS.md` を読みます。`AGENTS.md` には「`CLAUDE.md` の決まりに従う」ことと、仕組みの違いによる読み替え（呼び名、保存のしかたなど）だけを書いているので、ルールを直すときは `CLAUDE.md` と手順書（`.claude/skills/`）だけを直せば、3つのAIすべてに反映されます。

| ファイル | 内容 |
| --- | --- |
| `CLAUDE.md` | 全体のルール（話し方、進め方、触ってよいファイル、守ること） |
| `.claude/skills/news/SKILL.md` | ニュースの作り方（記事ごとに必要な情報を洗い出す → 完成案 → 保存） |
| `.claude/skills/recruit/SKILL.md` | 採用情報（募集一覧、仕事、社員紹介、よくある質問、新しい職種）の変え方 |
| `.claude/skills/edit/SKILL.md` | 文章の修正、画像の差し替え、取り下げ、「確認中」の表示の消し方 |
| `.claude/skills/photo/SKILL.md` | 写真の選び方と加工（ぼかし・切り抜き・トーン）。写っている人の顔や文字の確かめ方 |
| `.claude/skills/illustration/SKILL.md` | 写真がないときのイラストの描き方 |
| `.claude/skills/design/SKILL.md` | デザイン（色・文字・余白など）の変え方 |
| `.claude/skills/restore/SKILL.md` | 前の状態に戻すやり方 |

## 2. 使い方

### 依頼する

1. リポジトリの **「Issues」タブ → 「New issue」** を押します
2. タイトルに短い説明、本文に `@claude` とやりたいことを書いて「Create」を押します。写真は本文にドラッグ＆ドロップすれば添付できます
3. 1〜3分ほどで、Claudeがコメントで返事をします
4. 返事にはコメントで答えます。**コメントの先頭に `@claude` を付けてください**（付けないとClaudeは反応しません）

### 依頼の例

| やりたいこと | 書き方の例 |
| --- | --- |
| ニュースを出す | `@claude 2月の展示会の出展を告知したい`（案内状の画像を貼ってもよい） |
| 記事の相談をする | `@claude 何かニュースを出したいです。おすすめはありますか？` |
| 求人を増やす | `@claude グリーンプラの営業の募集を1件増やしたい`（求人票の画像を貼ってもよい） |
| 求人を直す | `@claude 倉吉工場の製造スタッフ（正社員）の給与を「月給22万円〜」に変えて` |
| 職種を増やす | `@claude 飲食の職種を増やしたい`（職種のページ・社員紹介・求人に要る情報を、AIがまとめて聞き返す。エントリーフォームの「ご希望の職種」の選択肢は、管理者が Xserver で足す） |
| 募集を締め切る | `@claude 倉吉工場の製造スタッフ（パート）の募集を締め切って` |
| 文章を直す | `@claude トップの「捨てるを、つくるに変える。」の下の紹介文を〇〇に変えて` |
| 写真を差し替える | `@claude アライアンスのページの新潟工場の写真をこれに変えて`（写真を貼る） |
| 写真を外す | `@claude お問い合わせのページの写真を外して`（外すと形が崩れる場所の写真なら、AIが理由を伝えて差し替えを提案する） |
| 「確認中」を消す | `@claude オープン採用の文面はこれで確定です。確認中の表示を消して` |
| 記事を取り下げる | `@claude 「2024NEW環境展」のニュースを消して` |
| 前の状態に戻す | `@claude 昨日公開したニュースを、公開前の状態に戻したい` |
| 消したものを戻す | `@claude 前に出していた倉吉工場のパートの募集をもう一度出したい` |

### AIを選ぶ

| 呼び方 | AI |
| --- | --- |
| `@claude ○○したい` | Claude |
| `@chatgpt ○○したい` | ChatGPT |
| `@gemini ○○したい` | Gemini |

- 返事をするときも、**同じAIの名前**を先頭に付けます（ChatGPTに頼んだら `@chatgpt これでOK`）
- 1つのコメントで呼べるAIは1つだけです（2つ以上書くと、どれも動かず、そのことをお知らせします）
- 1つのIssueでは、なるべく1つのAIを使ってください。途中でAIを変えた場合も、前のAIが保存した下書きを引き継いで作業します
- ChatGPT・Gemini の返事は、「作業を始めました」というコメントが、終わったときに返事に置き換わる形で届きます

### 資料を添付して頼む

求人票や職種の依頼書、チラシなどは、PDF・Word（.docx）・Excel（.xlsx）・PowerPoint（.pptx）・テキスト・CSV のファイルのまま、Issueやコメントに添付できます（入力欄にファイルをドラッグします）。

- 例: 求人票の PDF を添付して `@claude この求人票で募集を追加して`、職種についてまとめた Word を添付して `@claude この資料で職種を追加して`
- 資料の書き方の形は決まっていません。メモ、メール、原稿、求人票など、手元にある形のままで大丈夫です
- AI は資料を読み取って案を作り、資料に書かれていないことや読み取れないことだけを質問します。案を確かめてから保存するのは、いつもと同じです
- Word に入っている写真も使えます（使う前に、写っているものを確かめます）
- 古い形式（.doc・.xls・.ppt）と、Googleドキュメントなどのリンクは読めません。新しい形式か PDF で保存し直して添付してください
- **リポジトリを非公開にしている場合、添付した資料は AI が読めません**（GitHub の仕組み上、ブラウザでログインした人しか取り出せないため）。その場合は、下の「資料置き場」を使うか、資料を開いて中身をコピーし、コメントに貼り付けてください（PDF はページの画面を撮って画像で貼っても読めます）。貼った写真は、非公開でも読めます。資料を読めなかったときは、AI がそのことと、渡し方を返事で知らせます

#### 資料置き場（非公開のリポジトリのとき）

リポジトリの `inbox` フォルダが「資料置き場」です。資料を入れてから、Issue に名前を書いて頼みます。

1. 資料置き場（`https://github.com/<アカウント>/<リポジトリ>/upload/main/inbox`。ブックマークしておくと便利です）を開き、資料をドラッグして、緑の「Commit changes」を押します
2. Issue に `@claude 資料置き場の「営業_原稿.docx」で更新して` のように、資料の名前を書いて頼みます（「.docx」などは省けます）

- **AI が読むのは、そのIssueで名前を書いた資料だけです。** 前の依頼の資料が残っていても読みません（AI が作業する場所からは、資料置き場が見えないようにしてあります）
- 名前の「.docx」は省いて書けます。パソコンが付けた「 (1)」「 - コピー」などが名前の後ろにあると、AI は勝手に選ばず「これのことでしょうか」と確かめます（合っていれば、名前を最後まで書いて頼み直します）
- Issue に資料を添付してしまったときは、AI が「資料置き場にアップして、指示し直してください」と入れ方を案内します。同じ名前のまま資料置き場に入れたら、`@claude 資料置き場に入れました` とコメントすれば続きから進みます
- 前から置いてある資料の名前を書いたときは、使う前に AI が確かめます。名前が見つからないときは、置いてある資料の名前を示して、どれか聞きます
- 資料置き場に入れただけでは、本番サイトの公開は動きません
- いらなくなった資料は、資料を開いて「…」→「Delete file」で消せます。入れた資料は、消しても変更の記録には残ります（見られるのは招待された人だけです）
- 公開のリポジトリでは使わないでください（入れた資料を誰でも見られるため）
- 添付した資料は、頼まない限りサイトには載りません（「このPDFを記事に載せて」と頼めば載せます）

### 確認して公開する

1. AIが保存すると、1〜2分後にIssueに **「確認用ページを更新しました」** というコメントが届きます。今回変わったページのURLも並びます（上部に黄色い「確認用ページです」の帯が出ます）
2. 直したいところがあれば、同じIssueで `@claude ○○を直して` と頼みます
3. 問題がなければ、**AIの最新の返事** の下にある **「Create PR」** のリンクを押し、開いた画面で **「Create pull request」** を押します。これが公開申請です
4. 公開申請のページで **「Squash and merge」→「Confirm squash and merge」** を押します。2〜3分後に本番サイトに反映されます
5. 元のIssueが開いたままなら、「Close issue」で閉じます

### 注意

- **1つのIssueでは、1つの用件**を扱います。別の用件は新しいIssueで依頼してください
- 確認用ページでは、お問い合わせ・エントリーのフォームは表示されません（本番サイトだけで動きます）
- 新しいページの追加、メニューの変更、表示の仕方の変更は、Claudeは対応しません（管理者が行います）

### 困ったとき

| 困りごと | 対処 |
| --- | --- |
| Claudeが返事をしない | コメントに `@claude` が付いているか確認してください。Actionsタブで「Claude（Issueからの更新）」が失敗していないかも確認します |
| ChatGPT・Geminiが返事をしない | コメントに `@chatgpt`・`@gemini` が付いているか確認してください。Actionsタブで「ChatGPT・Gemini（Issueからの更新）」の結果を確認します。「1-5」の API キーが登録されていないと動きません |
| 確認用ページのURLが届かない | Actionsタブで「確認用ページを更新」の結果を確認します。失敗している場合は「1-3」の設定を見直してください |
| 確認用ページが変わらない | 反映まで1分ほどかかります。ページを再読み込みしてください |
| 急いで本番から消したい | 「Pull requests」タブの「Closed」から、その内容を公開したときの公開申請を開き、一番下の「Revert」→ 新しくできた公開申請で「Squash and merge」→「Confirm squash and merge」を押すと、2〜3分で元に戻ります |

## 3. 仕組みの詳細

### フォルダの構成

```
├── site/                  サイトの中身（サーバーのアップロード先にそのまま置かれる）
│   ├── index.html など     各ページのHTML（data/ の JSON を読み込んで中身を表示する）
│   ├── data/               ニュース、採用情報、会社情報、製品の中身（JSON）
│   └── assets/             CSS、JavaScript、画像、PDF
├── tools/                 チェックと公開用のファイルづくり、画像の調整、画面の撮影
├── CLAUDE.md              AIへの作業ルール（Claude が読む。ChatGPT・Gemini も AGENTS.md から読む）
├── AGENTS.md              ChatGPT・Gemini 向けの読み替え
├── .claude/skills/        AIの作業手順（3つのAIで共通）
└── .github/               自動処理の設定
```

### ワークフロー

| ファイル | 動くとき | すること |
| --- | --- | --- |
| `claude.yml` | Issueやコメントに `@claude` が書かれたとき | Issueの画像と添付された資料をダウンロードし、Claudeが返事・作業をする。下書きを保存したら確認用ページを作る |
| `ai.yml` | Issueやコメントに `@chatgpt`・`@gemini` が書かれたとき | 頼んだ人の権限を確かめ、Issueの画像と添付された資料をダウンロードし、ChatGPT か Gemini が返事・作業をする。AI が作業する環境には保存の権限を持たせず、別のまっさらな環境で `site/` の中の変更だけを取り込んで下書きに保存し、確認用ページを作る（前後の処理は `.github/scripts/ai_run.py`） |
| `preview.yml` | AIが下書きを保存したとき（`claude.yml`・`ai.yml` から呼び出される） | チェックして確認用のファイルをそろえ、GitHub Pages に公開し、URLをコメントで知らせる |
| `deploy.yml` | main に反映されたとき、毎朝6時ごろ | チェックして本番用のファイルをそろえ、Xserver のアップロード先（シークレット `FTP_SERVER_DIR`）にアップロード、公開の記録（タグ）を残す |

### 公開用のファイルづくり（`tools/build.py`）

`site/` を `dist/` に写し、次のことを行います（担当者やClaudeが直すのは、これまでどおり `site/` の JSON と文章だけです）。

- JSON の書き方の誤り、記事のフォルダや画像の見落としをチェックする（誤りがあれば公開しない）
- ニュースの「下書き」「非公開」「日付が未来」の記事と、求人の「下書き」「非公開」を、本番用から外す
- 画像やCSSを差し替えたとき、ブラウザに古いものが残らないよう、`?v=` の番号を付け直す
- ページを一度ブラウザで開き、JSON から表示された中身を、そのまま HTML に書き込む（事前の書き込み）。JSON を読む表示処理はページから外す。検索エンジンやSNSでも中身が読めるようにするため。ニュース一覧の絞り込み・ページ送りは、JSON を読まない別の処理にしてあるので、そのまま動く
- すべてのページに書き込めたら、`data/` フォルダ（JSON）を外す。**本番・確認用のサーバーには JSON を置かない**。1ページでも書き込めなければエラーにして止める（本番は前の状態のまま）
- ページごとに、SNSで共有されたときのタイトル・説明・画像（OGP）を書き込む。画像とURLには本番のアドレス（シークレット `SITE_URL`）を使う。登録がないときは、画像とURLを書かない
- 確認用では、黄色い帯を出し、検索エンジンに載らないようにし、フォームを表示しない

### 手元で試す

```
pip install -r requirements.txt
python tools/build.py --check      # チェックだけ
python tools/build.py --preview    # 確認用を dist/ に作る
python tools/build.py              # 本番用を dist/ に作る
python tools/remove.py news 20251210        # 記事を消す（openings 番号 / jobs フォルダ名 / people 番号）
python tools/remove.py photo contact-hero.jpg   # 写真をページから外す（外せる場所だけ）
python tools/history.py list               # 前に消したものの一覧（show で中身、restore で戻す）
python tools/photo_sheet.py                # 貼られた写真の一覧（grid で目盛り付き、zoom で拡大、compare で並べる）
python tools/prepare_image.py 元 保存先 --blur-face X1,Y1,X2,Y2 --crop 3:4 --focus X,Y --tone auto   # 写真の加工
```

`dist/` のページは中身が書き込まれているので JSON は要りませんが、リンクや画像の場所を正しく見るため、`python -m http.server -d dist` などで小さなWebサーバーを立てて見てください。
`--no-prerender` を付けたときだけは書き込みをしないので、`data/` が残り、ページは JSON を読んで表示します（手元での確認用）。
