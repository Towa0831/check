# 文章の修正・画像の差し替え・写真を外す・取り下げ

CLAUDE.md の「依頼の種類と進め方」に沿って進める。

## 1. 直す場所を探す

担当者は、ページの見た目やURLで場所を伝えてくる。文章は **JSON（`site/data/`）と HTML（`site/**/index.html`）の両方** にあるので、次の順で探す。

1. 担当者が書いた文言（直したい元の文章）で検索する
   - Grep で `site/data/` と `site/` の `*.html` を検索する（例:「捨てるを」「倉吉工場」を探す）
   - 文章の途中に改行や `<br>` が入っていることがあるので、見つからなければ短い言葉で探し直す
2. URLやページ名で伝えられたら、下の表で探す場所を絞る

| ページ | 文章のありか |
| --- | --- |
| トップ（`site/index.html`） | 大きな見出し、紹介文、各欄の見出しは HTML。数字・循環・代表メッセージ・参画企業（社名・ロゴ画像・ロゴのリンク先）は `site.json`、ニュース欄は `news.json`、採用欄は `recruit.json` |
| アライアンス（`site/alliance/`） | 各社・拠点・数字・沿革・物語などは `site.json`、製品は `products.json`、ページの見出しは HTML |
| ニュース（`site/news/`） | 記事はすべて `news.json`。一覧ページの説明文は `site/news/index.html` |
| 採用情報（`site/recruit/` の各ページ） | `recruit.json`（各社の名前は `site.json`）。中身の変更は recruit の手順書に従う |
| お問い合わせ・エントリー | 各ページの `index.html`。フォームそのものは別の仕組みなので、ここでは直せない（管理者に相談） |
| ヘッダー・フッター | メニュー・サイト名・コピーライトは、すべてのページの `index.html` に同じものが書かれている。フッターの「関連サイト」だけは `site.json` の `related`（全ページに自動で入る） |

- 見つからない、または **同じ文言が複数の場所にある** ときは、場所の候補を見せて、どれを直すか（全部か）を確認する
- ヘッダーやフッターのように全ページ共通の部分は、すべてのページを同じように直す（1ページだけ直すと、ページによって表示が違ってしまう）
- 依頼が「新しいページを作りたい」「メニューを変えたい」「表示の仕方を変えたい」などのときは、対応せず管理者に相談するよう伝える（ニュースの記事は news、職種・社員紹介を増やすのは recruit の手順書で対応する）

## 2. 文章を直す

- 直し方が具体的（「〇〇を△△に」）なら、すぐ保存してよい。返事に **変更前 → 変更後** を書く
- 「もっと分かりやすく」「やわらかく」など、言い回しを考える必要があるときは、修正案を示してOKをもらってから保存する
- 日付に曜日を書くときは `python tools/build.py --weekday 日付` で確かめる

### JSON を直すときの決まり

- 直すのは `"…"` の中の文字だけ。項目の名前、`[ ]` `{ }` の形、`,` の位置は変えない
- 文字の中で改行するところは `\n` と書く。`"` を使うときは `\"` と書く
- 直したら必ず `python tools/build.py --check` を実行する（書き方の誤りがあると、そのページが表示されなくなるため）

### HTML を直すときの決まり

- 基本は、タグの間の文字だけを直す。タグ、`class`、`id`、`<script>` の中身は変えない
- `<br>` や `<span class="…">` などで文章が分かれているときは、その分け方を保ったまま直す
- 次の軽微な修正は、HTML でもしてよい（下の「リンク・題名」も見る）
  - 今あるリンクの行き先（`href="…"` の中だけ）
  - 文章の中の言葉にリンクを付ける（その言葉を `<a href="…">言葉</a>` で囲む。`class` や `target` は付けない）
  - 画像の差し替え（下の「3」）と、画像の説明（`alt="…"`）
  - ページの題名（`<title>…</title>`）と、検索結果などに出る説明文（`<meta name="description" content="…">` の `content` の中）
  - `<script>` の中に書かれた、画面に出る短い文字（グラフの見出しなど）。文字だけを直し、記号（`` ` `` `'` `"` `$` `{` `}` `<` `>`）は変えない。直したら必ず `python tools/build.py --preview` で、そのページが「作れませんでした」にならないことを確かめる
- 要素（欄・ボタン・メニューの項目・写真の枠など）を足す・消す・並べ替えるのは、仕組みの変更。対応せず、管理者に相談するよう伝える。写真を外すのは、下の「4」の道具で、外せる場所だけ（自分で `<img>` を消すと `--check` がエラーにする）

### リンク・題名を直す

リンク先のアドレス（URL）は、**担当者から聞いたもの、または資料に書かれたものだけ**を使う。推測したり、検索して見つけたりしない。分からなければ聞く。

| 頼まれること | 直すところ |
| --- | --- |
| フッターの「関連サイト」を足す・消す・名前やアドレスを直す・並べ替える | `site.json` の `related`。`{ "name": "表示する名前", "url": "https://…" }` を並べた順に表示される。全ページのフッターに自動で入るので、HTML は直さない |
| 参画企業のロゴを押したら、その会社のサイトに移るようにする／移り先を変える | `site.json` の `companies` の、その会社の `url`。`url` がある会社のロゴは、押すとそこへ移る。アライアンスのページの会社カードにも、そのアドレスへのリンクが出る。`url` のない会社に足してよい |
| ロゴの画像を入れる・替える | `site.json` の `companies` の `logo`（`/assets/img/…` から書く。画像は下の「3」の手順で保存する） |
| ページの中のリンクの行き先を変える | そのページの `index.html` の `href="…"`。同じリンクがほかのページにもないか Grep で確かめ、あれば全部直すかを確認する |
| 文章の中の言葉にリンクを付ける | HTML の文章なら `<a href="…">言葉</a>` で囲む。JSON の文章（ニュースの本文など）は、その JSON に「リンク」の項目があるときだけ（ニュースは `link` の段落）。ないときは管理者に相談 |
| ページの題名・説明文（検索結果に出る文）を変える | そのページの `index.html` の `<title>` と `<meta name="description" content="…">` |

- サイトの中のページへのリンクは、そのページから見た場所で書く（例：トップから `alliance/`、ニュース記事から `../../recruit/`）。`--check` が、リンク先のページがあるかを確かめる
- サイトの外へのリンクは、`https://` から始まるアドレスで書く（`site.json` の `related`・`url` は、`--check` が形を確かめる）
- 返事には、変更前 → 変更後（名前とアドレス）を書く。確認用ページで、リンクを実際に押して確かめてもらうよう添える

## 3. 画像を追加・差し替える

1. `/tmp/issue-images/list.txt` で、使う画像を確認する。画像が複数あり、どれを使うかはっきりしないときは確認する
   - 写真は、先に photo の手順書（`claude/skills/photo/SKILL.md`）で、選ぶ・写っているもの（ほかの人の顔、読める文字）を確かめる・必要なら切り抜き／トーン調整をしてから保存する（ぼかしは、頼まれて、精度のことを伝えて確かめたあとだけ）
2. どこに使うかがはっきりしないときは、候補を示して確認する
3. 画像を整えて保存する。差し替えのときも、**元の画像は上書きせず、新しい名前で保存する**（古い画像は履歴として残し、ブラウザに古い画像が残る問題も防ぐ）
   ```
   python tools/prepare_image.py /tmp/issue-images/image-1.jpg site/assets/img/photo/exterior-2026.jpg
   ```
4. 画像を指定している場所を、新しいファイル名に書き換える
   - JSON の中：`"/assets/img/photo/exterior-2026.jpg"` のように `/assets/` から書く
   - HTML の中：`src="../assets/img/photo/exterior.jpg?v=…"` のように、そのページからの場所で書かれている。ファイル名の部分だけを書き換え、`?v=…` はそのまま残す（公開のときに自動で付け直される）
   - 古いファイル名がほかで使われていないか、Grep で確認する
5. 画像の説明（`alt`、JSON では `alt` や `img` の近くの説明の項目）は、画像の内容が分かる短い文にする
6. 返事には、どこの画像をどう変えたかと、整えた結果（サイズなど）を書く

イラストを新しく描く・描き直すときは、`claude/skills/illustration/SKILL.md` に従う。

## 4. 写真を外す

「この写真を外して」「お問い合わせの写真を消して」「インタビューの途中の写真を説明ごと消して」と頼まれたら、`python tools/remove.py photo` で外す。自分で HTML の `<img>` や JSON の写真の項目を消さない（`--check` がエラーにする）。

外せるのは、外してもページの形が崩れない次の場所だけ。

| 外せる場所 | 外すとどうなるか |
| --- | --- |
| ページの見出しの下の大きな写真（アライアンス・募集一覧・よくある質問など） | 写真の枠ごとなくなり、見出しのすぐ下に中身が来る（ニュース一覧などと同じ形） |
| ニュースの記事の本文の写真 | その写真だけがなくなる |
| 社員紹介のインタビューの途中の写真 | 写真と説明（キャプション）がなくなり、前後の質問がつながる |

それ以外（トップのスライド、写真の並び、カード、背景、職種や社員紹介の人物写真、製品の写真、ロゴなど）は外せない。道具が理由を出して止まり、ファイルは何も変わらない。担当者に理由を伝え、別の写真に差し替える（上の「3」）ことを提案する。どうしても外したいときは、ページの作りを変えることになるので、管理者に相談するよう伝える。

1. どの写真かを決める。担当者が書いたページ・場所・説明（キャプション）から、写真の名前を探す（ページの HTML の `src="…"`、`site/data/` の JSON の `/assets/img/…`）。同じ場所に写真が何枚もあって、どれか決まらないときは、候補を見せて確かめる
2. `python tools/remove.py photo 写真の名前`（例: `contact-hero.jpg`）を実行する
   - 1か所だけで使っている写真は、そのまま外れる。外したあと、どこでも使わなくなった画像のファイルも消える（変更の記録には残るので、戻せる）
   - 2か所以上で使っている写真は、使っている場所の一覧（番号付き）が出て止まる。担当者の依頼に合う場所を選び、`python tools/remove.py photo 写真の名前 番号` でもう一度実行する（どこか迷ったら担当者に確かめる）
   - 「外せません」と出たら、何も変わっていない。理由を担当者に伝え、差し替えを提案する
3. 見出しの下の写真を外したときは `python tools/screenshot.py after ページの場所`（例: `contact/`）で、パソコンとスマートフォンの画面を撮って確かめる。ニュースやインタビューの写真のときは `python tools/build.py --preview`
4. `python tools/build.py --check` を実行して保存する（CLAUDE.md の「保存のしかた」）
5. 返事には、どのページのどの写真を外したか（変更前 → 変更後。インタビューなら説明の文も）を書き、「また載せたくなったら `@claude 外した〇〇の写真を戻して` と頼めば、元どおりに戻せます」と添える

外す写真が1枚に決まる依頼（「お問い合わせの写真を外して」など）は、提案を省いてすぐ保存してよい。

## 5. ニュースを取り下げる（削除）

取り下げは、**消す**のが基本。消したものは変更の記録に残っていて、あとで探して戻せる（restore の手順書）。

1. 対象の記事を決める。タイトルが1つに決まるときは、確認を待たずに進めてよい。はっきりしないときは、記事の一覧（タイトル・日付）を番号付きの表で見せて選んでもらう
2. `python tools/remove.py news フォルダ名` で消す。記事の中身、ページのフォルダ、その記事だけで使っていた画像・資料が一緒に消える（ほかでも使っている画像は残る）
   - ファイルを消すのは、この道具だけを使う。自分でファイルやフォルダを消さない
3. 「ほかの場所に、このページへのリンクがあります」と出たら、そのリンク（関連記事のリンクなど）を外すか、別のページに変えるかを担当者に聞く。決まるまでは保存しない（`--check` もエラーになる）
4. `python tools/build.py --check` を実行して保存する（CLAUDE.md の「保存のしかた」）
5. 返事には、**どの記事を消したか**（タイトルと日付）と、一緒に消えた画像があればそのことを書き、最後に「また載せたくなったら `@claude 消した〇〇の記事を戻して` と頼めば、元どおりに戻せます」と添える

消すと、確認用ページの一覧と記事のページから消える。公開ボタンを押すと、本番からも消える（記事のURLを開くと「見つかりません」になる）。

### 消さずに隠すとき（非公開）

担当者が「サイトには残しておきつつ、見えないようにしたい」「一時的に隠したい」のように、**残しておくことをはっきり頼んだときだけ**、消さずにその記事に `"status": "非公開"` を付ける。見せるときは `status` を消す。迷ったら、消すか隠すかを聞く。

募集一覧の求人を締め切るときは、recruit の手順書に従う。

## 6. 「確認中」の表示を消す

ページの「確認中」の印は、制作中の確認メモ。担当者が「この内容で確定した」と言ったときだけ消す。

- JSON の `todo`（や `〇〇Todo`）の項目：中身を空にする（`"todo": ""`）。`true` になっているものは `false` にする。項目そのものは消さない
- 文章の頭の「【仮】」：その文章が確定したら「【仮】」を消す
- HTML の `<p class="todo">…</p>`：その `<p>` を丸ごと消してよい（このときだけ、タグを消してよい）
- どの「確認中」を消すのかがはっきりしないときは、ページにある「確認中」の一覧を見せて確認する

## 7. 保存

CLAUDE.md の「保存のしかた」に従う。
